# Обмін Raspberry Pi і робота

Координати кромок стика передаються по RS485, протокол Modbus RTU.

## Параметри лінії

| Параметр | Значення |
|---|---|
| Інтерфейс | RS485, плата RS485 CAN на Raspberry Pi |
| Протокол | Modbus RTU |
| Швидкість | 9600 бод |
| Формат кадру | 8 біт даних, без парності, 1 стоп-біт (8N1) |
| Адреса пристрою | 1 |
| Порт на Raspberry Pi | `/dev/ttySC0` |
| Пристрій у програмі робота | `modbus_dev m`, порт `rtserMB0` |
| Таймаут відповіді на Raspberry Pi | 1 с |

Raspberry Pi працює як master: клас `minimalmodbus.Instrument` це клієнт, він сам формує запити. Контролер робота відповідає як slave з адресою 1. Програма робота нічого не надсилає, вона лише зчитує дані, які отримав її Modbus-пристрій: `read(m, redata, 0, 8)`.

## Регістри

Raspberry Pi записує чотири регістри 16 біт функцією 16 (Write Multiple Registers). Кожен регістр записується окремим викликом `write_register(n, value, functioncode=16)`.

| Регістр | Зміст | Одиниці |
|---|---|---|
| 0 | X1: правий край лівого відрізка лазерної лінії | px |
| 1 | Y1: середина лівого відрізка по висоті | px |
| 2 | X2: лівий край правого відрізка | px |
| 3 | Y2: середина правого відрізка по висоті | px |

Значення беззнакові, діапазон 0...2027 по X і 0...1519 по Y для кадру 2028×1520. Кадр записується лише тоді, коли знайдено рівно два відрізки. Якщо їх немає, регістри зберігають останні записані значення.

## Розбір у програмі робота

Робот зчитує 8 байтів, копіює їх у системні змінні `$I[0...7]` і збирає значення. Молодший байт іде першим:

```
camera_x1 = $I[1]*256 + $I[0]
camera_y1 = $I[3]*256 + $I[2]
camera_x2 = $I[5]*256 + $I[4]
camera_y2 = $I[7]*256 + $I[6]
camera_center = (camera_x1 + camera_x2) / 2
```

Центр стика `camera_center` це середина зазору між двома відрізками по горизонталі. Він порівнюється з опорним значенням, яке запам'ятовується на старті програми.

## Оцінка швидкодії

Оцінка зроблена за арифметикою кадрів Modbus RTU, на реальному обладнанні частоту оновлення не вимірювали.

Один запис одного регістра функцією 16:

| Кадр | Байти | Склад |
|---|---|---|
| Запит | 11 | адреса 1, функція 1, початковий регістр 2, кількість 2, лічильник байтів 1, дані 2, CRC 2 |
| Відповідь | 8 | адреса 1, функція 1, початковий регістр 2, кількість 2, CRC 2 |

Усього 19 байтів. Кожен байт займає на лінії 10 біт (старт, 8 біт даних, стоп), тобто 190 біт, що при 9600 бод дає 19,8 мс. До цього додається обов'язкова пауза не менше 3,5 символа перед кожним кадром, близько 3,6 мс. Разом на один запис приблизно 27 мс.

| Варіант | Час на оновлення координат | Найвища частота |
|---|---|---|
| Чотири окремі записи (як у програмі) | близько 80...110 мс | близько 10 Гц |
| Один запис чотирьох регістрів (25 байтів) | близько 30...35 мс | близько 30 Гц |

Час обробки кадру додається до цих значень. Отже, швидкість каналу 9600 бод обмежує частоту оновлення координат, і один запис чотирьох регістрів прискорив би обмін приблизно втричі.

## Швидкість корекції в роботі

Програма робота виконує крок по Y на 1 мм і за кожен крок зсуває X на частку виміряного відхилення (коефіцієнт `corection_factor`). Відхилення за n кроків зменшується як `(1 - k)^n`, де k це коефіцієнт.

| Коефіцієнт | Де використано | Відхилення зменшується в e разів | Відхилення зменшується до 5 % |
|---|---|---|---|
| 0,05 | робоча програма | за 20 кроків (20 мм ходу) | за 58 кроків |
| 0,25 | варіанти з перериваннями | за 3,5 кроку | за 10 кроків |

Зона нечутливості 0,125 мм при 15 px/мм дорівнює приблизно 1,9 px. Один піксель відповідає 0,067 мм.
